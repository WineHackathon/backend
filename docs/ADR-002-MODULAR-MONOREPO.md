# ADR-002: Переход на модульный монорепозиторий и интеграция Вкусовой матрицы

## Статус
**Принято (Accepted)**

## Контекст и проблематика
Критерий оценки хакатона ЛЦТ 2026 формулируется следующим образом:
> **«Архитектура (15/100) — качество разделения функционала внутри репозитория, воспроизводимость»**

Изначальная архитектура из 7 независимых нано-сервисов порождала избыточную сложность сетевого взаимодействия (например, отдельный `recognition-service`, который лишь перекладывал задачу в Redis Streams для `ml-service`), усложняла запуск и тестирование стенда. Кроме того, требовалось реализовать продуктовые сценарии:
1. Ограничение для неавторизованных пользователей (лимит 5 сканов по `X-Device-Fingerprint` + IP) и пейволл в сомелье.
2. 5-вопросный онбординг сомелье с адаптивными ветвлениями и интерактивным стримингом по WebSockets.
3. Обогащение базы вин многомерной **Вкусовой матрицей** (Taste Matrix) и алгоритмом подбора вин.

## Принятое решение
Перестроить проект в **Модульный монорепозиторий (Modular Monorepo)** с разделением на 5 целевых слоев:

1. **`application/` (Слой данных и бизнес-логики)**:
   - Вся работа с базой данных вынесена в данный слой по аналогии со структурой `Архив (2)/telegram/applications`:
     - `adapters/database/`: фабрика асинхронных сессий, `TransactionManager` (`async with tm:`), модели SQLAlchemy 2.0, репозитории (`repositories/`).
     - `dto/`: Pydantic v2 схемы.
     - `services/`: прикладные сервисы (`catalog_service`, `user_service`, `cellar_service`, `taste_profile_service`, `auth_service`).
2. **`backend/` (Единый API Gateway / BFF)**:
   - Единая точка входа для всех HTTP-клиентов (`/v1/eval/predict`, `/api/v1/ml/scan`, `/api/v1/catalog`, `/api/v1/users`, `/api/v1/auth`, `/api/v1/sommelier`).
   - Защита от абуза: Redis `X-Device-Fingerprint` + IP счетчик (лимит 5 сканов с возвратом `registration_required: true`).
3. **`ml/` (Выделенный ML-слой)**:
   - Модели извлечения визуальных эмбеддингов (MobileNetV3 / ResNet), векторный индекс с HMAC-SHA256 верификацией целостности, воркер Redis Streams.
4. **`sommelier/` (Специализированный сервис AI-сомелье)**:
   - Сценарий «Оптимальный первый диалог» (5 стартовых вопросов + адаптивные ветвления).
   - **WebSocket-эндпоинт (`/ws/sommelier`)** для интерактивного стриминга диалога.
   - Движок подбора по вкусовой матрице (4D евклидово расстояние + сходство ароматов по Жаккару).
5. **`infrastructure/` (Инфраструктура и оркестрация)**:
   - Единый `docker-compose.yml`, Nginx Gateway с поддержкой WebSocket Upgrade (`/ws/sommelier`), MinIO S3, PostgreSQL 16, Redis 7 (AOF).

## Последствия
- **Плюсы**:
  - Высокая связность внутри слоев и слабая связанность между ними (High Cohesion, Loose Coupling).
  - Устранение накладных расходов на лишние сетевые прыжки между нано-сервисами.
  - Идеальная воспроизводимость стенда: `docker compose up --build` и `./scripts/run_all_tests.sh`.
  - Выполнение всех требований чекера хакатона (SLA < 1 сек на `/v1/eval/predict`).
- **Компромиссы**:
  - Необходимость четкого контроля импортов между пакетами (проверяется статическими тестами).
